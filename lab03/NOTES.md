git diff сравнивает две версии и показывает, что изменилось между ними.

git show показывает один конкретный коммит

git log показывает список истории

git log -S ищет коммиты, в которых появилась или пропала указанная строка (я искал "def").

git blame показывает для каждой строки файла, в каком коммите и кем она написана.



git restore lab03/calc.py возвращает файл к состоянию последнего коммита и стирает мои несохранённые правки.

git restore --source=HEAD\~2 lab03/calc.py берёт версию файла из указанного коммита (здесь на два коммита назад), а не из последнего.



git revert HEAD не стирает коммит из истории, а создаёт новый коммит, который отменяет изменения предыдущего.

git reset --hard двигает ветку назад и полностью удаляет коммиты (и правки) из истории, то есть переписывает её.



Тег v1.0 это постоянное имя для конкретного коммита: по нему удобно обращаться

Отличие тега от ветки: ветка подвижная и сдвигается вперёд с каждым новым коммитом, а тег всегда указывает на один и тот же коммит и не двигается.



Рискованные правки делают не в main, а в отдельной ветке: я создал experiment командой git switch -c experiment, добавил деление с проверкой нуля и закоммитил.

Потом вернулся в main и влил ветку командой git merge --no-ff experiment. Ключ --no-ff создаёт отдельный коммит слияния, по которому видно, что была ветка.

После слияния ветку удалил командой git branch -d experiment.

Если бы эксперимент не удался, ветку можно было бы просто удалить, а main остался бы нетронутым.
